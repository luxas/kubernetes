## 1. What landed

Two files, +41/-0 (`git diff fa5423953d4^1 fa5423953d4 --stat`).

- `staging/src/k8s.io/apiserver/pkg/admission/conversion.go:62-68`: new method
  `func (v *VersionedAttributes) GetOldObject() runtime.Object`. It returns `v.VersionedOldObject.object` if that is
  non-nil, and otherwise falls back to the embedded `v.Attributes.GetOldObject()`. It is a copy of the existing
  `GetObject` override at `:54-60`.
- `staging/src/k8s.io/apiserver/pkg/admission/conversion_test.go:168-199`: new `TestObjectAccessors`. It builds
  internal `example.Pod` new and old objects, calls `NewVersionedAttributes` to `example.apiserver.k8s.io/v1`, and
  checks that both accessors return `*examplev1.Pod` with TypeMeta set and the right names.
- No feature-gate check. No API change. No change to `NewVersionedAttributes` (`:91-113`, which still reads
  `attr.GetOldObject()` through the interface at `:97`) or to `ConvertVersionedAttributes` (`:172-…`, which reads
  `attr.Attributes.GetOldObject()` explicitly at `:179`).

Why it matters: `VersionedAttributes` is what the enforcer passes as `authorizer.ConditionsData`
(`plugin/authorizer/conditionsenforcer/conditionsenforcer.go:106,146`). The `ConditionsData` contract
(`pkg/authorization/authorizer/interfaces.go:338-340`) says the old object "should be versioned in the external
version corresponding to GetKind()". Before this PR, `GetOldObject()` broke that contract for built-in types.

### Security

- **[Question] [code] Ungated change to mutating-webhook objectSelector input for CRs.** Path:
  `plugin/webhook/mutating/dispatcher.go:128-133` → `predicates/object/matcher.go:60`. See A3. A mutating webhook
  whose objectSelector should match on old-object labels can now be skipped (or invoked) differently from 1.37 when
  an earlier webhook's version conversion rewrites labels. Admission webhooks are often security controls, so a
  skip is a potential bypass, although the preconditions are narrow and the new behaviour is the more consistent one.
  Fix: state it in the release note, or accept it explicitly in `decisions.md`. Gating is not worth it (see Clarity).
- Fail-open check (A1): none found. Checked: before the PR, the built-in-type ACR path failed closed
  (`webhook.go:478`). After it, the GVK check still guards any internal object that slips through via the fallback
  (`conversion.go:67`). The in-process CEL path never used the accessor. The `PossibleDecisions` guard
  (`conditionsenforcer.go:147-149`) is unaffected.
- TOCTOU: the old object the enforcer sees is the storage object inside the update/delete transaction
  (`registry/rest/update.go:292`, `rest/delete.go:189-191`, a deep copy). Conversion happens per admission call, so
  a conflict retry re-converts. This PR introduces nothing new here.
- Leakage, DoS, cache key: not applicable. The accessor allocates nothing and touches no cache (the `celVal`
  cache is only touched by `Set`/`CELValue`).

### Bugs

Task focus (b), create/update/delete:

- UPDATE: `VersionedOldObject` is set by `NewVersionedAttributes:97-103`, and its GVK equals `a.GetKind()`
  (`ConvertToGVK:86`, or the identity at `:74-75`). Correct.
- CREATE: in-tree handlers pass an untyped nil old object (`endpoints/handlers/create.go:182`,
  `update.go:176,214`, `rest/create.go:234` from static attrs). `VersionedOldObject` stays zero, and the fallback
  returns `Attributes.GetOldObject()`, which is untyped nil. The webhook skips it (`webhook.go:472-474`), so
  `RawExtension{Object:nil}` marshals as `null`. Correct.
- DELETE: the old object is `old.DeepCopyObject()` (`rest/delete.go:191`) and the object is nil, so it is converted
  like UPDATE. Correct by reading. No test (see Tests).
- Typed nil: if a caller supplied a typed-nil *struct* old object, `NewVersionedAttributes:97` would treat it as
  non-nil, and `ConvertToGVK:74` would call `GetObjectKind()` through a nil pointer and panic. That would surface
  as a 500 via panic recovery, which fails closed. This is pre-existing, also affects VAP and webhooks, and is not
  introduced here. The only way for `GetOldObject` itself to return a typed nil is the fallback, and only when the
  attrs carry one.

Findings:

- **[Nit] [code] `NewVersionedAttributes` reads through the overridden accessors.** At
  `staging/src/k8s.io/apiserver/pkg/admission/conversion.go:97,104`, if `attr` is itself a `*VersionedAttributes`,
  the old object is now sourced from the already-versioned copy (as the new object already was via `GetObject`).
  `scheme.Convert` between two external built-in versions has no direct conversion func, so this fails. Before the
  PR, at least the old object converted from internal. `ConvertVersionedAttributes:179` avoids the problem by using
  `attr.Attributes`. No in-tree caller nests these (C above). Fix: unwrap `*VersionedAttributes` at the top of
  `NewVersionedAttributes`, or document "attr must not be a *VersionedAttributes".
- **[Nit] [code] The fallback silently mixes versions.** At `conversion.go:64-67`, a `VersionedAttributes` built as
  a struct literal with `VersionedObject` set but not `VersionedOldObject` returns a versioned new object and an
  internal old object. That breaks the `ConditionsData` contract (`interfaces.go:338-340`), and the webhook and
  in-process paths then see different old objects (internal vs `null`). It is unreachable in non-test code: the
  only literal is `conversion.go:93`. Struct literals exist only in tests. Fix: none needed. Optionally document
  that the fallback exists only for unconverted (nil) objects.

### KEP alignment

- **[Nit] [KEP] Old-object version is not specified.** KEP `review/kep.md:1946-1947` says: "The new (request)

  `GetKind()`'s version (`interfaces.go:336-340`, `conversion.go:62-68`, `conditionsenforcer.go:106`). **Fix KEP**:
  the code is the only coherent choice, because a condition must be one version-specific expression over both

- **[Nit] [KEP] `ConditionData` sketch differs from the code.** KEP `:689-701` says `GetObject` is "prior to default

  (`interfaces.go:341`). The enforcer is a validating plugin and sees the post-mutation, post-defaulting object.
  **Fix KEP**: describe `ConditionsData` as built (a subset of `admission.Attributes`, objects external in
  `GetKind()`'s version, as seen after mutating admission).

### Clarity / completeness

- **[Nit] [code] Gate (task focus (c)).** The change is ungated, and that is acceptable. Gating an accessor on a
  generic admission type would need feature-gate plumbing in `k8s.io/apiserver/pkg/admission`. The only in-tree

- **[Nit] [code] The doc comment does not say what the method returns.** At `conversion.go:62`, "GetOldObject

  `Condition.Evaluate` implementations (`evaluate.go:125`). Fix: "returns the old object converted to
  VersionedKind if set, else the original; callers must not mutate it". The same applies to `GetObject` at `:54`.
- **[Nit] [code] Misleading comment in the webhook.** At `plugin/pkg/authorizer/webhook/webhook.go:475`, "Callers

## 5. Verdict

The merged code is correct and sound for alpha. It is a necessary fix: without it, every conditional UPDATE or
DELETE of a built-in type evaluated by an ACR webhook would fail closed at `webhook.go:478`. Its only ungated
effect in tree is the narrow mutating-webhook objectSelector case for label-rewriting CRD conversions, and the new
behaviour there is more consistent than before. Before beta:
- add an end-to-end row in which the old object alone causes a deny, in every variant;
- extend `TestObjectAccessors` to create, delete, re-conversion and identity;
- record the ungated objectSelector change as an accepted decision with a release note;
- fix the KEP to say that both objects are external in `GetKind()`'s version.

The single most important finding is the test gap: no integration test can tell old from new, so a regression that
fed the new object as `oldObject` (the security-relevant direction, letting a user "launder" a violating object
through an update) would pass CI. Only the fake-authorizer unit test in `conditionsenforcer_test.go:461-479` would
catch it.
