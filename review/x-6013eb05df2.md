## Findings

### Critical (must fix before merge)

None. The integration test structure is thoughtful and exercises the full feature end-to-end.

### Important (should fix)

1. **Only the `"using-webhook-only"` CEL variant is active.** `conditionalauthorization_test.go:` (near `celConditionalAuthorizerVariants`). The `"in-process-eval-only"` and `"if-in-process-fails-call-webhook"` variants are commented out. The commit body acknowledges this. But the branch as it stands is going to alpha with only *one* evaluation path exercised. Highlight in the PR body that in-tree CEL evaluation is untested pre-alpha; it will land in a follow-up.
2. **CRD conversion + HPA v1/v2 tests exercise the "aggregated-server-shape" of the KEP indirectly** — but the classifier explicitly returns false for aggregated-server-owned groups (from `67711704058`). Verify whether these tests actually cover the aggregated-API-server path or just multi-version conversion of built-in APIs. If the latter, the aggregated-server story isn't tested end-to-end.
3. **Test uses `defer webhookServer.server.Close()` inside `runConditionalAuthorizationTests` (a test helper).** Standard Go practice, but for a long-running integration test the deferred close might not fire in time if a subtest panics. Consider `t.Cleanup(...)` for symmetry.
4. **`goleak.IgnoreTopFunction("net/http.(*persistConn).readLoop"|"writeLoop")` in `main_test.go` masks a known leak (well-documented via the comment).** This is a real issue in `apiextensions-apiserver`'s webhook.ClientManager. Filing a follow-up to fix the underlying cache would let us remove these ignores. Comment as-is is excellent guidance.
5. **The `expectAllowedWhenDisabled` field lets a test case behave differently under FG-off vs. FG-on.** Good design; verify that "fall-through to RBAC" is the actual test expectation for the disabled case (per the docstring).

### Nits

- Test file at 2004 lines is unwieldy — consider splitting the "test scaffolding" (webhook server, testAuthorizer, celEvaluateCondition) into a `helpers_test.go`, keeping `conditionalauthorization_test.go` focused on the test cases themselves.
- The commented-out variants (`in-process-eval-only`, `if-in-process-fails-call-webhook`) should be replaced with `t.Skip` calls or gated by a `TODO(luxas)` comment referencing the follow-up issue for the built-in CEL evaluator.
- CRD conversion test file at 514 lines and HPA at 341 lines — both file names describe the scope well.
- The framework change to `etcd.go` (+9) — verify it doesn't affect other integration tests that use `framework.EtcdMain(m.Run)` without goleak options.

### Questions

- Are the tests deterministic? Integration tests with webhook servers on random ports can be flaky in CI. Any retries built in?
- Test coverage of `HandledDecisionTypes` variants — does the table exercise a request that sets only `{Allow, Deny, NoOpinion}` (conditions-unaware client, FG on) to verify the classic path?
- Test coverage of the "conditional decision returned by webhook to conditions-unaware client" fail-close path?

### Coverage (of the KEP's production surface)
- **Well covered end-to-end:**
  - Unconditional Allow/Deny/NoOpinion via webhook.
  - Conditional Allow evaluated by ACR round-trip (webhook only; in-tree CEL variant is commented out).
  - Conditional Deny (fold to Deny).
  - Deny precedence over Allow within a Union chain.
  - Operation-aware conditions (CEL referencing `request.operation`).
  - CRD conversion webhook path (via `crd_conversion_test.go`) — proves the ACR + admission versioning interoperates.
  - HPA v1/v2 old/new-object under UPDATE — the multi-version conversion at admission time.
  - Feature-gate on and off (Enabled/Disabled runners).
- **Missing / thin:**
  - **In-tree CEL evaluator variants**: `"in-process-eval-only"` and `"if-in-process-fails-call-webhook"` are commented out awaiting the built-in evaluator (Important #1 in main review). Currently only the webhook-only path is exercised.
  - **Aggregated API servers**: the classifier rejects aggregated-owned groups, so the current integration tests do not exercise the aggregated-API-server story end-to-end. CRD conversion is the closest analog, but it's not a true aggregated server.
  - **Compound authorization for connect verbs**: no test asserts that `ensureAuthorizedForVerb` (`pkg/registry/core/pod/rest/authorize.go`) still uses the `UnconditionalAuthorizer` interface — a regression here would silently fail-close conditional decisions on connect requests.
  - **update→create compound authz**: the `staging/src/k8s.io/apiserver/pkg/endpoints/handlers/update.go` compound check is not exercised for conditional decisions (not implemented yet, but no test verifies the current fail-closed behaviour either).
  - **Silent fallback path** (Critical #3 in `00-summary.md`): FG on + `AuthorizationConditionsEnforcer` disabled — no integration test verifies the API server silently reverts to `WithAuthorization` (which is the current behaviour). Add a `TestConditionalAuthorizationEnforcerDisabled` that toggles the plugin off.
  - **ACR UUID correlation across API server replicas**: single-replica test; no multi-replica assertion. If a stateful load balancer routes SAR to replica A and ACR to replica B, does correlation still work? Probably yes (UUID travels with the request), but not tested.
  - **`HandledDecisionTypes` variants** on the wire: the tests appear to fix `HandledDecisionTypes` for the whole run; no matrix over `[Allow, Deny, NoOpinion]` (unconditional) vs. the full conditional set.

### Structure
- 2004 lines in `conditionalauthorization_test.go` — the reviewer's biggest concern. Split into:
  - `conditionalauthorization_test.go` — TestMain scaffolding, top-level test entrypoints.
  - `helpers_test.go` — `newWebhookServer`, `testAuthorizer`, `celEvaluateCondition`, `celConditionalAuthorizerVariants`.
  - `cases_test.go` — the actual test table.
- The `main_test.go` goleak ignores are a **known-leak workaround**. A follow-up ticket to fix `apiextensions-apiserver`'s webhook.ClientManager would let these ignores be removed.
- `expectAllowedWhenDisabled *bool` — pointer for tri-state (nil = use expectAllowed, non-nil = override). Consider `expectAllowedWhenDisabled  authorizer.Decision` for clarity, but the current shape works.

- `conditionalauthorization_test.go` — commented-out variants (`in-process-eval-only`, `if-in-process-fails-call-webhook`) — should be replaced with `t.Skip("TODO: reactivate when in-tree CEL evaluator lands, tracked at <issue>")` for visibility.
