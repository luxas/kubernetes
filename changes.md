# Comprehensive Review for the Conditional Authorization feature

Your task is to review a large set of changes for the Kubernetes Conditional Authorization feature.
Context about the high-level goals and rationale of the feature can be found in `kep.md`, however, if there are discrepancies between the KEP and the code, this should be flagged as a finding.
The review MUST be conducted on a commit-by-commit basis.
The output of the review MUST be markdown files of `review/<commit-sha>.md`, no code changes.

Look at least at the following aspects, first for each commit individually, and finally for all of the changes as a whole:

- Are there any bugs with regards to achieving the full vision, or locally in functions? If there are, flag as a finding.
- Do the unit and integration tests actually test the production code comprehensively? If they do not, flag as a finding.
- Are there security issues in the current implementation? This access control feature is obviously high-stakes as it relates to security, so it's critical that there are e.g. no OWASP risks present 
- Use the `code-review` plugin as well, with a treshold of 60 (instead of the default 80) to flag potential issues. DO NOT post anything to GitHub or anywhere externally, just write files on disk.
- Are all parts of the code appropriately feature-gated, so all changes are backwards-compatible?
